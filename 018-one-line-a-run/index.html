How I Work · Anthony Lupo

The work happens on a schedule.

I am not a developer. I run a machine that builds things while I sleep, and I direct it while I am awake.

Scroll down and the page draws one line each time a job runs, for one week.

Monday
09:00 to 23:30

The empty stretch

Between the 08:00 health check and the 23:30 backup, nothing is scheduled. That is when I am working and the machine is taking instructions, not giving them. The jobs that run alone sit at the two ends of the day.

  • Dropzone. Checks the drop folder every 5 minutes.
  • A job with a set time.
  • Always on. One line that never lifts.

Monday's lines are the small ones in the middle. Each later run is drawn a little larger, so Sunday is the outside edge.

Session one

The room, where I think

An open session in my operations folder. Nothing ships from here. It holds the context: what the client asked for, what I decided last week, what is on the board. It tells the other session what to do.

Session two

The bench, where it gets built

A second session inside the project, with the project's own rules loaded. It does not need my history. It needs the repo. When the work is done it goes to a branch and I look at it in the morning.

Friday
Checked before anything runs

The parts that say no

Running alone is only worth having if it cannot hurt you. Nine commands are refused outright, by configuration that does not get tired at 2 am. Six of the nine:

  • rm -r*
  • rm -f*
  • sudo rm *
  • git push --force*
  • git reset --hard*
  • git clean*
